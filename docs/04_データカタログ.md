- 作成日：2026-09-09
- 作成方法：`docs/research/A〜D` の WebSearch 調査結果と `docs/02_要件定義書.md` 第 6 章・第 16 章、`docs/03_スコアリング仕様.md` 第 2 章を統合。追加のオンライン確認は行っていない（WebFetch・curl 不可のため）。
- 対応する機械可読版：`data/catalog.json`（第 1〜2 章のみ収録）
- 表記ルール：
  - 「確からしさ」は `確認済み`（一次情報相当のURL・記述が複数の調査で一致）／`推定`（存在は確からしいが属性・規約等の細部が未検証）／`未確認`（本調査では裏付けが取れなかった）の3段階。
  - URL が特定できないものは **絶対に URL を捏造せず「未確認」と明記**する。
  - 「要検証 ID」は `docs/02_要件定義書.md` 第 16 章の V-01〜V-10 に対応。該当なしは空欄。

### 4-2. ODbL混在時の扱い

- OSM/Overture（ODbL）は本アプリの中核データである PLATEAU・国土数値情報・地理院・都データ（いずれも PDL1.0／CC BY 4.0 相当、Share-Alike義務なし）と法的性格が異なる。
- **推奨方針（案・要事業判断）**：OSM/Overture は「施設名称・地下出入口候補のクロスチェック用途」に限定し、オープンデータ層として一般公開する建物特徴量テーブル（DR-04）には ODbL 由来の属性値をそのまま組み込まない。組み込む場合は、当該テーブル全体を ODbL の Share-Alike 条件（同等ライセンスでの再配布義務）に従わせるか、法的に「実質的抽出（substantial extraction）」に該当しない範囲に留める必要がある。
- 自治体データインポート由来分（東京都・区市がOSMにインポートした形跡があるデータ）は個別の許諾条件が上乗せされている可能性があり、利用前に個別確認が必要（未確認、本調査では特定できず）。
- DR-04・DR-05（要件定義6-2）との関係：非公開層（Tier1/2の回答・設備位置）には元々ODbLは関与しない。公開可能なオープンデータ層にOSM/Overture由来の値を混ぜる設計にする場合は、この節の方針をスコアリング仕様・ETL設計側で明文化する必要がある。

## 矛盾・要検討事項（統合作業中に判明したもの）

1. **国土数値情報 P02/P05（公共施設）**：要件定義 6-1 では検証状況「確認済み」と記載されているが、調査A（建物データ調査）は P04・P14・P29 のURLは確認したものの P02/P05 のURLは取得できていない。本カタログでは URL を「未確認」として扱い、6-1側の「確認済み」表記を見直すか、追加調査で裏付けを取ることを推奨する。
2. **「確認済み」の粒度差**：要件定義 6-1 は「データセットの存在」を指して「確認済み」としている行（S12/N02、P04/P14/P02・P05 等）と、要件定義 16 章 V-10 が指摘する「利用規約本文（商用利用可否の明文）は未検証」が両立している。本カタログでは両者を区別し、`data/catalog.json` の `commercial_use` は規約本文が明文で確認できたもの（PLATEAU、A31、地理院標高タイル、地形分類ベクトルタイル、不動産情報ライブラリAPI）のみ `"yes"`、それ以外は `"unknown"` とした。
3. **PLATEAU対象区データの版のばらつき**：調査Aは「東京23区一括データ（2020・2022年度版）」の存在を確認しているが、要件定義6-1が指定するのは個別区版「目黒区2025年度・世田谷区2023年度」であり、年度が異なる。本カタログは6-1の個別区版を正としたが、どちらのデータを実装で採用するかは要件定義側の明確化が望ましい。
4. **武蔵小杉タワーマンション事例の停止期間**：調査D内で「電気復旧まで約17日（10/29）」（日経クロステック）と「生活正常化まで約1ヶ月、建物によっては1〜3ヶ月」（別記事）という幅のある記述が併存し、一意の数値が確定できない。`docs/05_検証事例集.md` では両方を併記し「推定」とした。
5. **地下出入口データの受け皿不在**：要件定義6-1「任意」データとして OSM/Overture の entrance タグ（地下出入口候補）が挙げられているが、`config/features_schema.json` には対応するフィールド（地下入口有無・位置等）が定義されていない。現状は features スキーマ側に受け皿がないため、`osm_overture_poi` の `feeds_fields` は `name` / `alt_facility_dist_m` に限定した。地下入口候補を Tier 0 特徴量として使うならスキーマ拡張の検討が必要（本タスクではスキーマ変更は行っていない）。
6. **東京都浸水予想区域図と国土数値情報A51の関係**：調査Bは「PoCの内水評価は A51 ではなく都のGISデータが主軸になる可能性が高い」としているが、要件定義6-1では A51 を「推奨（第二ソース・クロスチェック）」と明確に位置づけており矛盾はない。両者は主・副の関係として本カタログでも整合させた。
