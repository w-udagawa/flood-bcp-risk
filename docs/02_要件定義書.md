## 1. 目的と位置づけ

### 1-1. 解決する問題

洪水・内水ハザードマップは「どこにどれだけ水が来るか」を示すが、「その水が建物のどの機能を止めるか」は示さない。同じ浸水深でも、受変電設備・非常用発電機・中央監視・排水ポンプが地下や低層にある建物は、浸水後に全館停電・長期休業に至る。2025 年 9 月 11 日の局地的豪雨で目黒区自由が丘の商業施設「フレル・ウィズ自由が丘」が地下 1 階の受変電設備水没により全館停電し、12 月 5 日の営業再開まで約 3 か月休業した事例（東急ストア公式発表・報道、`docs/research/B_ハザードデータ調査.md` 参照）が、この問題の典型である。

### 1-2. 製品の定義

> オープンデータから、浸水した場合に建物機能・事業が長期停止する可能性が高い建物を建物単位で抽出し、根拠・不足情報・対策候補とともに提示する一次スクリーニングツール。

本製品は安全性を保証するものではなく、詳細調査の優先順位付けを支援する。この免責は全画面・全出力に表示する（NFR-08）。

### 1-3. 成功の定義（PoC）

1. 既知の被災建物（自由が丘事例を含む公開事例）が、オープンデータのみで対応優先度 A または B に入る。
2. 専門家が重要と判断する建物の上位 20 件と、本システムの上位 20 件の重なりが 50% 以上。
3. 管理者向け簡易診断（12 問）の回答により、優先度が変わる建物が生じ、その変化が専門家から妥当と評価される。
4. 全評価建物について、等級ごとの根拠データ・出典・取得日を建物カルテに表示できる。

## 4. スコープ

### 4-1. MVP（PoC で実装する範囲）

- 対象エリア：目黒区・世田谷区の全建物のうち、用途が住宅（戸建・小規模共同住宅）以外、または延床面積 3,000 ㎡以上の建物。
- Tier 0（オープンデータ）自動評価、Tier 1（簡易診断）による再評価。
- 地図（2D）、建物カルテ、管理施設一覧、簡易診断フォーム、レポート出力。
- スコアリング仕様（`03_スコアリング仕様.md`）とデータカタログ（`04_データカタログ.md`）。

### 4-2. フェーズ 2

- 渋谷区・大田区・川崎市への拡張、高潮レイヤ有効化。
- Tier 2（現地調査）入力と確定リスク。
- DEM 流下方向・集水面積解析による流入方向・プラバリア候補線の表示。
- 対策前後比較。
- 3D 表示（CesiumJS + PLATEAU 3D Tiles 配信サービス）。

### 4-3. フェーズ 3

- 降雨予測・水位・浸水センサー連携、施設別アラート、タイムライン。
- GI 導入効果の簡易試算。
- 画像解析による地下入口・換気口候補抽出。

### 4-4. 対象外

- 津波、土砂災害。
- 人命リスク評価（避難計画）。
- 建物の構造的被害（家屋倒壊等氾濫想定区域は表示のみ）。
- 保険料算定。

## 5. 評価ロジック（概要。詳細は `03_スコアリング仕様.md`）

### 5-1. 評価の構造

```text
[H] ハザード等級 0〜4     建物地盤面での想定水位・実績・地形補正
[V] 流入脆弱性等級 0〜4   水が地下・低層の設備空間に届きやすいか
[I] 事業影響度等級 0〜4   停止したときの利用者・地域への影響
[C] データ確信度 0〜100%  入力データの有無・鮮度・Tier

H × V ──マトリクス──▶ [P] 設備被災可能性 0〜4
P × I ──マトリクス──▶ [優先度] A / B / C / D
C が低い場合 ──▶ 優先度を 1 段階引き上げ、"*" を付す
```

### 5-2. Tier（情報段階）

| Tier | 情報源 | 更新者 | 評価への使い方 |
|---|---|---|---|
| 0 | オープンデータのみ | システム（自動） | 初期等級 |
| 1 | 管理者向け簡易診断 12 問 | 施設管理者 | V・I の上書き、C の加点 |
| 2 | 現地調査・図面確認 | 技術者 | 確定等級（フェーズ 2） |

### 5-3. 出力

建物ごとに、優先度、P/H/V/I/C、各等級の根拠（データ名・値・出典・取得日）、不足情報リスト、優先確認事項、対策候補、評価ステータス（評価済 / 評価不能 / 対象外）を出す。

### 6-2. データ管理要件

- DR-01：全データについて、出典・版・取得日・ライセンス・座標系・加工内容を `data/catalog.json` に台帳化する。
- DR-02：座標系は内部では JGD2011 平面直角座標系第 9 系（EPSG:6677）で演算し、配信は WGS84（EPSG:4326 / Web メルカトル）に変換する。
- DR-03：ハザードデータは元の浸水深階級（下限・上限）を保持し、等級化は後段で行う。ソースごとの階級定義の違いを吸収する。
- DR-04：オープンデータ層（建物・ハザード・地形・スコア Tier 0）は公開可能な形で配布できるが、施設名と紐づく優先度の公開は D-15 に従う。
- DR-05：Tier 1/2 の回答・設備位置は非公開層に保存し、オープンデータ層とは建物 ID のみで結合する。

## 8. 非機能要件

| ID | 要件 |

| NFR-01 | 説明可能性：全等級が入力値と規則から一意に再現できる。機械学習モデルは MVP で使わない |

| NFR-09 | 更新性：ハザード・PLATEAU の更新時に ETL 再実行で全件再評価できる |
| NFR-10 | 監査：Tier 1/2 の入力者・日時を記録 |

## 9. データモデル（論理）

## 10. アーキテクチャ

```text
[取得]  ダウンロードスクリプト（PLATEAU/東京都/国土数値情報/地理院タイル）
   │     requires: requests, geopandas, rasterio, plateau-gis-converter
   ▼
[ETL]   pipelines/  CityGML→GeoPackage、空間結合、DEM集計、特徴量テーブル(Parquet/CSV)
   │     requires: geopandas, duckdb(spatial), rasterio, whiteboxtools(任意)
   ▼
[評価]  floodbcp/   純Pythonスコアリングエンジン（標準ライブラリのみ）
   │     入力: features.csv/json  出力: assessments.json/csv
   ▼
[配信]  tiles/      tippecanoe → PMTiles、静的ホスティング（S3等）
        web/        MapLibre GL JS 静的フロント（カルテ・一覧・フィルタ）
   │
   ▼
[非公開層] api/    FastAPI + PostgreSQL/PostGIS（施設登録、簡易診断、評価履歴、認証）
```

- オープンデータ層は静的ファイルで完結し、非公開層なしでも地図とカルテを閲覧できる。
- 非公開層は施設登録・簡易診断が必要な段階で追加する。

## 13. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| PLATEAU 建物付与浸水属性・地下階数の収録率が低い | V・H の確信度低下 | 東京都浸水予想区域図との空間結合で H を二重化。地下階数欠損は規模・用途からの推定値と低確信度で扱う |
| 東京都浸水予想区域図の階級が粗い | H の分解能不足 | 階級下限で等級化し、上限を根拠に併記。DEM 相対標高で補正 |
| 浸水実績が GIS で取れない | 実績フラグ欠損 | 区の実績図 PDF をジオリファレンスして手動ポリゴン化（PoC は目黒区・世田谷区のみ） |
| 誤判定（見逃し・過大） | 信頼低下 | 確信度表示、専門家レビュー、検証集合での指標公開 |
| スコア公開による風評 | 法的・営業リスク | D-15。施設名付きの公開は同意ベース |
| ライセンス違反（ODbL 混在） | 配布不可 | 台帳管理。MVP は OSM/Overture を補助情報に限定 |
| ネットワーク制約で実データ検証ができない（本開発環境） | 未検証事項の残存 | 第 16 章の検証タスクをローカル環境で先行実施 |

## 15. 用語

| 用語 | 定義 |
|---|---|
| 内水氾濫 | 下水道・水路の排水能力を超えた雨水による浸水 |
| 外水氾濫（洪水） | 河川の氾濫による浸水 |
| 想定最大規模 | 1,000 年に 1 回程度の降雨（東京都浸水予想区域図は 153 mm/h・690 mm/24h） |
| 受変電設備 | 高圧で受電し建物内で降圧する設備。浸水すると全館停電 |
| Tier | 情報段階（0：オープンデータ、1：管理者入力、2：現地調査） |
| PMTiles | 単一ファイルで配信できるタイルアーカイブ形式 |
