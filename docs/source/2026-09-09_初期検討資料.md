# 浸水時事業停止リスク診断アプリ 検討資料

- 作成日：2026年9月9日
- 検討テーマ：オープンデータを活用した、浸水時に建物機能・事業継続へ重大な影響が生じる可能性のある建物の抽出
- 想定対象：商業施設、駅・交通施設、オフィス、病院、福祉施設、物流施設、データセンター、公共施設等
- 本資料の位置づけ：初期構想・PoC検討用

---

## 0. エグゼクティブサマリー

### 背景

都市型豪雨では、建物への浸水そのものだけでなく、地下や低層部に設置された受変電設備、中央監視設備、非常用発電設備、給排水設備等が被災することで、建物全体の機能停止や長期休業につながる可能性がある。

2025年9月11日の集中豪雨では、東急ストア「フレル・ウィズ自由が丘」の地下1階が浸水し、電気供給等に関わる基幹設備が故障したため、設備復旧に伴い約3か月の休業を余儀なくされたことが社内共有資料に記載されている。

この事例が示す重要点は、被害の大きさが単純な浸水深だけで決まるのではなく、**「浸水した高さ・場所に、どのような重要設備が存在したか」**によって大きく変わることである。

### アプリの基本コンセプト

> **浸水する建物を探すのではなく、浸水した場合に建物機能や事業が長期間停止する可能性が高い建物を抽出する。**

オープンデータを用いて、以下の3要素を建物単位で評価する。

1. **ハザード**：どの程度の水が建物周辺に来る可能性があるか
2. **建物脆弱性**：水が内部・地下へ入り、重要設備へ到達しやすいか
3. **事業影響度**：浸水時に建物機能、利用者、地域サービスへどの程度影響するか

### 結論

- オープンデータのみでも、**高リスク建物の一次スクリーニング**は可能と考えられる。
- 一方、受変電設備等の設置階、止水設備、防水区画、排水ポンプの冗長性等は公開情報から把握できない場合が多い。
- したがって、現実的な構成は以下の二段階とする。
  - 第1段階：オープンデータによる自動スクリーニング
  - 第2段階：施設管理者による簡易診断または現地調査
- 最終的には、診断結果から、設備かさ上げ、防水化、止水板・プラバリア、浸水検知センサー、雨水貯留、グリーンインフラ等の対策候補を提示する。

## 1. 解決したい課題

### 1-1. 既存のハザードマップだけでは分からないこと

洪水・内水ハザードマップは、地域ごとの浸水想定深等を確認するうえで有用である。一方、同じ浸水想定深の建物であっても、実際の事業停止リスクには大きな差がある。

例：同じ50cmの浸水でも影響は異なる。

- 倉庫の床や什器の一部が浸水する
- 地下駐車場のみが浸水する
- エレベーターピットが浸水する
- 受変電設備が浸水し、全館停電となる
- 中央監視設備が浸水し、建物設備の制御が不能となる
- 給排水ポンプが停止し、衛生設備を使用できなくなる

このため、地域のハザードだけでなく、建物ごとの脆弱性と機能停止時の影響を組み合わせて評価する必要がある。

### 1-2. 現状の実務上の課題

- 対象建物が多く、全施設を現地調査することは難しい
- どの建物から詳細調査すべきか、優先順位を付けにくい
- 建物設備情報は非公開または分散管理されている
- 浸水対策が止水板、排水設備、設備更新等の個別対策に分かれ、総合評価されにくい
- 浸水後の復旧期間や事業停止損失まで考慮した評価が少ない
- ハザード情報と施設管理情報、センサーデータ、対策履歴が一元化されていない

## 3. 評価ロジックの全体像

### 3-1. 基本式

初期版では、説明可能性を重視して以下の構造とする。

```text
建物水害機能停止リスク
= ハザード × 建物脆弱性 × 事業影響度
```

ただし、初期PoCでは乗算だけに固定せず、加重合計方式との比較も行う。

```text
総合スコア
= ハザードスコア × WH
+ 建物脆弱性スコア × WV
+ 事業影響度スコア × WI
+ 確信度補正
```

- `WH`：ハザードの重み
- `WV`：建物脆弱性の重み
- `WI`：事業影響度の重み
- `確信度補正`：データの有無・精度・更新時期を反映する補正

### 3-2. リスク評価とデータ確信度を分ける

公開情報だけでは、地下設備の位置等を確定できない。このため、リスクの高さとデータの確からしさを別々に表示する。

例：

- リスク：高、確信度：高
- リスク：高、確信度：低、現地確認推奨
- リスク：中、重要設備情報なし
- リスク：評価不能、データ不足

これにより、「情報がないから安全」と誤認することを防ぐ。

## 4. 評価項目案

> 以下の配点は初期検討用の仮案であり、公的基準として確定した値ではない。PoCで被災実績・専門家意見と照合して調整する。

### 4-1. ハザードスコア：40点（仮）

| 評価項目 | 内容 | 主なデータ候補 |
|---|---|---|
| 洪水浸水想定 | 想定浸水深、浸水継続時間 | 国・都道府県・自治体の洪水浸水想定区域 |
| 内水浸水想定 | 短時間豪雨時の下水道能力超過による浸水 | 自治体の内水ハザードマップ・内水浸水想定区域 |
| 高潮・津波 | 沿岸部の浸水可能性 | 高潮・津波浸水想定データ |
| 過去浸水実績 | 過去に浸水・冠水が確認された地域 | 自治体の浸水実績図、災害記録 |
| 地形・標高 | 窪地、谷底低地、周囲より低い敷地 | 国土地理院標高・地形分類 |
| 流入集中性 | 道路勾配、周辺地形、建物配置による水の集中 | 標高データ、道路、PLATEAU等 |
| 河川・水路近接 | 河川、暗渠、水路、低地との位置関係 | 国土数値情報、自治体GIS |

### 4-2. 建物脆弱性スコア：35点（仮）

| 評価項目 | 内容 | 自動評価の可否 |
|---|---|---|
| 地下階の有無・可能性 | 地下空間が存在する、または存在可能性が高い | データによる。要確認の場合あり |
| 地下出入口 | 地下駐車場スロープ、地下街接続、搬入口 | 一部自動、画像・現地確認併用 |
| 地盤面との関係 | 建物入口が道路面より低い、低地側に開口がある | 標高・3D形状から推定可能性あり |
| 大規模建物 | 流入口が多い、地下設備を有する可能性 | 建築面積・延べ面積等から代理評価 |
| 建築年・構造 | 既存対策や設備更新状況の代理指標 | PLATEAU等、収録時のみ |
| 重要設備の低層配置 | 受変電・発電・監視・ポンプ等が地下・1階 | 原則、管理者入力・現地調査 |
| 止水設備 | 止水板、防水扉、かさ上げの有無 | 原則、管理者入力・現地調査 |
| 排水能力 | 排水ポンプ、非常電源、逆流防止等 | 原則、管理者入力・現地調査 |
| 防水区画・冗長性 | 浸水が建物全体に波及する構成か | 原則、管理者入力・図面確認 |

### 4-3. 事業影響度スコア：25点（仮）

| 評価項目 | 内容 | 主な考え方 |
|---|---|---|
| 施設用途 | 駅、病院、商業施設、福祉、物流等 | 地域生活・安全への影響 |
| 建物・施設規模 | 延べ面積、階数、テナント数等 | 利用者・入居者への影響の代理指標 |
| 地域拠点性 | 周辺住民の生活を支える施設か | 食料、医療、交通、行政等 |
| 代替性 | 近隣に代替施設があるか | 代替施設までの距離等 |
| 全館停止可能性 | 一部浸水が全館停電等へ波及するか | 設備構成に関する管理者入力 |
| 復旧難易度 | 調達に時間を要する設備、特殊設備等 | 管理者・設備事業者情報 |
| 過去被害 | 過去の浸水、休業、設備故障 | 公開情報、社内記録、報道等 |

## 6. オープンデータだけでは不足する情報

以下は、オープンデータのみでの把握が難しい、または確定できない可能性が高い。

- 受変電設備の設置階・設置高さ
- 非常用発電機の設置階・燃料供給系統
- 中央監視設備・制御盤の位置
- 給排水ポンプ・排水ポンプの位置
- 地下階の用途
- ドライエリア、換気口、搬入口等の開口部高さ
- 止水板、防水扉、防水シャッターの有無
- 止水設備の設置作業時間・運用体制
- 防水区画の範囲
- ケーブル貫通部の止水状況
- 排水ポンプの能力・冗長性・非常電源接続
- 浸水時に全館停電となる配電構成か
- 重要設備の交換部品・調達期間
- 代替電源、代替拠点、在庫・業務継続方法

したがって、アプリ上では「不明」を明示し、不明項目が多い建物も確認対象として扱う。

## 7. 二段階診断の提案

### 第1段階：オープンデータによる自動スクリーニング

#### 入力

- 建物位置・形状・属性
- 洪水、内水、高潮等のハザード
- 標高・地形
- 過去浸水実績
- 施設用途・規模

#### 出力

- 建物単位の一次リスクスコア
- リスク要因の内訳
- データ確信度
- 詳細調査の推奨度
- 優先確認項目

#### 表示例

```text
建物A
総合リスク：高
情報確信度：中

主な要因：
- 内水浸水想定区域に位置
- 周辺より標高が低い
- 大規模商業施設
- 地下階の可能性あり

不足情報：
- 受変電設備の設置階
- 地下出入口の止水設備
- 排水ポンプの非常電源

推奨：現地確認を優先
```

### 第2段階：施設管理者による簡易診断

5分から10分程度で回答できるチェック形式を想定する。

#### 基本質問案

1. 地下階はあるか
2. 地下駐車場、地下出入口、地下街接続はあるか
3. 受変電設備は地下または浸水想定高さ以下にあるか
4. 非常用発電設備は浸水想定高さより上にあるか
5. 中央監視設備・主要制御盤は地下または低層部にあるか
6. 排水ポンプは停電時も作動するか
7. 止水板・防水扉はあるか
8. 止水設備の設置担当者・設置判断基準は決まっているか
9. 地下開口部ごとの止水高さは想定浸水深を上回るか
10. 重要設備が一系統のみで、故障時に全館停止する構成か
11. 代替電源・仮設電源接続口はあるか
12. 過去に浸水、漏水、停電、長期休業があったか

#### 詳細調査への移行条件案

- 浸水想定があり、重要設備が地下・低層部にある
- 地下入口があり、止水対策が不明または想定高さ未満
- 全館停止につながる単一設備が低い位置にある
- 過去の浸水・冠水履歴がある
- 地域拠点施設で代替性が低い
- データ不足が多く、リスクを否定できない

## 9. 対策提案ロジック

アプリの価値は、リスク表示だけでなく「何をすべきか」までつなげる点にある。

### 9-1. 建物への流入を防ぐ

- 止水板
- 防水扉
- 防水シャッター
- 出入口・換気口・ドライエリアのかさ上げ
- ケーブル・配管貫通部の止水
- 地下駐車場スロープの止水

### 9-2. 建物周辺の水を制御する

- プラバリア等による一時的な流向・流速制御
- 安全な越流部の設定
- 建物入口から離れた場所への誘導
- 地表排水経路の見直し

### 9-3. 流出ピークを下げる

- 雨水貯留槽
- 雨庭
- バイオスウェル
- 透水性舗装
- 植栽基盤への浸透
- 地下貯留浸透施設

基本コンセプト：

> **人工構造物で流れを受け止めて時間を稼ぎ、その間にグリーンインフラで貯留・浸透させ、処理能力を超える水だけを安全に越流させる。**

### 9-4. 重要設備への到達を防ぐ

- 受変電設備の上階移設
- 設備架台によるかさ上げ
- 防水区画化
- 電気室入口の防水化
- 非常用発電機・燃料系統の安全高さ確保
- 仮設電源接続口の整備
- 系統分離・冗長化

### 9-5. 初動を早める

- 浸水検知センサー
- 雨量・水位・カメラの統合監視
- 止水板設置判断の閾値設定
- 担当者・連絡網・設置手順の明確化
- 豪雨前の資機材準備

## 10. プラバリア・グリーンインフラとの連携

### 10-1. プラバリアの位置づけ

プラバリアを「完全止水設備」だけでなく、以下の機能を持つ可変的な雨水制御設備として位置づける。

- 水の流速を落とす
- 一時的に滞留させる
- 水の流向を変える
- 複数のGI施設へ流入を分散する
- 道路・広場から建物入口への流入を抑える
- 安全な越流地点を形成する

### 10-2. アプリでの活用方法

- 建物周辺の低地・流入方向を可視化
- プラバリア候補設置線を提示
- 設置前後の流向・湛水箇所を比較
- 近隣GIへの誘導可能性を評価
- GIの面積・浸透能力・貯留能力と流入量を比較
- 能力超過時の越流先を確認

### 10-3. 注意点

- 上流側の水深増加
- 隣接敷地への流入転換
- 避難経路の阻害
- 車両・歩行者への影響
- 端部からの集中越流
- 土壌飽和後のGI能力低下
- ごみ・土砂による閉塞

したがって、プラバリアは単独で評価せず、流入、滞留、浸透、越流、排水までを一体で検討する。

## 12. 学習・検証用データの考え方

### 12-1. 教師データ候補

- 浸水した建物
- 長期休業した建物
- 電気設備・機械設備が故障した建物
- 浸水したが営業・運用を継続できた建物
- 止水・かさ上げ等により被害を抑えた建物

### 12-2. 自由が丘事例から得られる示唆

- 地下階への浸水が基幹設備故障へ波及した

- 電気供給機能の故障が長期休業につながった
- 被害評価では、浸水範囲より設備機能への影響が重要である

### 12-3. 注意点

- 単一事例だけで重みを決定しない
- 被災事例と非被災事例の双方を収集する
- 「被災しなかった理由」が設備対策か、降雨条件かを分ける
- 公開情報と内部情報を混同しない
- 施設名を公開する場合は、情報の正確性と取扱いを確認する

## 17. 主な課題・リスク

| 課題 | 内容 | 対応方針案 |
|---|---|---|
| 地下設備情報の不足 | 公開情報だけでは重要設備位置を確定できない | 簡易診断・図面確認・現地調査を追加 |
| 内水データの地域差 | 自治体ごとに形式・精度が異なる | PoC対象地域を限定し、データ標準化 |
| 誤判定 | 高リスクの見逃し、低リスクの過大評価 | 確信度表示、専門家レビュー、実績検証 |
| 責任範囲 | スコアが安全保証と誤解される | スクリーニング用途であることを明示 |
| データ更新 | 建物改修やハザード更新を反映する必要 | 更新日管理、定期再計算 |
| 情報管理 | 設備位置は防災・セキュリティ上慎重な取扱いが必要 | 権限管理、公開領域と非公開領域を分離 |
| ライセンス | データごとに利用条件が異なる | 出典・利用条件台帳を整備 |
| 対策による副作用 | 止水で隣接地へ水を転送する可能性 | 周辺流況・越流先を含めて評価 |
| GI能力の限界 | 土壌飽和や目詰まりで能力低下 | 貯留・安全越流・維持管理をセット化 |

## 24. 現時点の提案

本構想は、単なるハザードマップではなく、以下を一連のサービスとして統合することで独自性が出る。

```text
高リスク建物の抽出
    ↓
設備・開口部の確認
    ↓
浸水時の機能停止リスク診断
    ↓
止水・防水・設備かさ上げ
    ↓
センサーによる早期検知
    ↓
プラバリアによる流向・流速制御
    ↓
雨水貯留・グリーンインフラによる流出抑制
    ↓
豪雨時タイムライン・BCP運用
```

東急ストアの事例を起点にすると、訴求点は明確である。

> **浸水深を見るだけでは、長期休業リスクは分からない。重要設備の位置と建物機能への波及まで見て、対策の優先順位を決める。**

この考え方を中心に、まずは限定エリア・限定用途でPoCを行い、オープンデータによる一次抽出の精度と、管理者入力による改善幅を確認することが望ましい。
