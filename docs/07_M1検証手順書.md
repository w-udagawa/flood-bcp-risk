## V-01: PLATEAU 建物モデル（目黒区・世田谷区）の属性収録率

- **検証事項**: 目黒区 2025・世田谷区 2023 の PLATEAU CityGML に
  `storeysBelowGround`・`uro:BuildingDetailAttribute`・浸水リスク属性
  （河川・内水・高潮）が何%の建物に収録されているか。
- **取得元 URL**:
  - 目黒区: `https://www.geospatial.jp/ckan/dataset/plateau-13110-meguro-ku-2025`
  - 世田谷区: `https://www.geospatial.jp/ckan/dataset/plateau-13112-setagaya-ku-2023`
- **取得手順（ログイン・API キー要否）**:
  1. 上記データセットページから CityGML 一式（zip）をダウンロードする。
     ログイン不要、政府標準利用規約 2.0 への同意のみ（`docs/04_データカタログ.md` 第1章記載）。API キー不要。
  2. PLATEAU GIS Converter（CLI/GUI いずれか）を導入し、CityGML を
     GeoPackage に変換する（`docs/04_データカタログ.md` 第5章 手順2）。
- **実行コマンド**:
  ```bash
  python3 tools/verify/gpkg_fill_rate.py path/to/meguro_2025.gpkg \
    --layer-like bldg,Building \
    --columns-like storeysBelowGround,storeysAboveGround,usage,BuildingDetailAttribute,Flooding,HighTide,Inland,River,depth,rank \
    --json-out docs/verification/_work/v01_meguro.json

  python3 tools/verify/gpkg_fill_rate.py path/to/setagaya_2023.gpkg \
    --layer-like bldg,Building \
    --columns-like storeysBelowGround,storeysAboveGround,usage,BuildingDetailAttribute,Flooding,HighTide,Inland,River,depth,rank \
    --json-out docs/verification/_work/v01_setagaya.json
  ```
  （`docs/verification/_work/` は結果ファイル置き場として各自作成してよい。任意のパスでよい。）
- **記録すべき結果**:
  - 対象レイヤ名、建物件数（`row_count`）
  - `storeysBelowGround`（地下階数）の非 null 率
  - 用途（`usage`）・計測高さ（`measuredHeight`）・建築年（`yearOfConstruction`）の非 null 率
  - 浸水リスク属性（`Flooding`/`HighTide`/`Inland`/`River`/`depth`/`rank` を含む列名）の有無と非 null 率。**列が1つも見つからない場合は「収録なし（0%相当）」として記録する**
- **判定基準**:
  - 地下階数（`storeysBelowGround`）の非 null 率が **80% 以上なら Tier 0（実測値）で使用**、80% 未満なら Tier 1〜2 の推定ロジック（`storeysBelowGround` 欠損時の代替推定式）を主として使う（タスクカード記載の基準をそのまま採用）。
  - 浸水リスク属性（河川・内水・高潮）が該当列自体存在しない、または非 null 率が実務上無視できる水準（目安: 10% 未満）の場合、`03_スコアリング仕様.md` の H（ハザード）算出において PLATEAU 由来のリスク属性は使わず、都データ（V-02）・国土数値情報 A31/A51/A49（既存確認済み）を一次ソースとする設計を維持する。10%以上の場合の閾値・扱いは実測値を見てから Fable が最終判断する（本手順書では暫定案のみ）。
  - 用途・計測高さ・建築年の非 null 率はいずれも参考値として記録し、`03_スコアリング仕様.md` 第1章の各フィールドの欠損補完ロジック（Tier 分け）の入力にする。
- **結果の反映先**: `docs/06_設計判断ログ.md`（属性収録率の実測値記録）、`docs/03_スコアリング仕様.md`（H・V の Tier 設計）、`docs/04_データカタログ.md` 第1章 #1 行の「確からしさ」欄。

## V-02: 東京都浸水予想区域図の属性・浸水深階級・座標系

- **検証事項**: 東京都浸水予想区域図（城南地区）Shape の属性・浸水深階級・座標系。
- **取得元 URL**:
  - データセットページ: `https://catalog.data.metro.tokyo.lg.jp/dataset/t000014d0000000029`
  - 参考（河川部ページ）: `https://www.kensetsu.metro.tokyo.lg.jp/river/chusho_seibi/panhulink/menu`
- **取得手順（ログイン・API キー要否）**: ログイン不要（推定、`docs/04_データカタログ.md` 記載）、API キー不要。データセットページから Shape 一式（zip、または個別 .shp/.dbf/.shx/.prj）をダウンロードする。
- **実行コマンド**:
  ```bash
  # 1. 属性を確認（.zip のまま指定可）
  python3 tools/verify/dbf_inspect.py path/to/tokyo_flood_jonan.zip \
    --top-n 30 --json-out docs/verification/_work/v02_dbf.json

  # 2. 浸水深階級コードが pipelines/config/depth_class_tables.json の想定と合っているか確認
  #    --field は 1. の出力を見て階級コードが入っているフィールド名に置き換える
  python3 tools/verify/depth_class_check.py docs/verification/_work/v02_dbf.json \
    --field <階級コードのフィールド名> --source tokyo_inundation_map
  ```
  座標系（.prj ファイル）は GIS ライブラリ不要のテキストファイルなので、
  `cat path/to/tokyo_flood_jonan/*.prj` 等でそのまま中身を確認し、
  `docs/04_データカタログ.md` に記載の「測地成果2011平面直角座標系第9系」
  と一致するか目視確認する（`dbf_inspect.py` の対象外）。
- **記録すべき結果**:
  - フィールド一覧（浸水深階級を表す列名、単位が m か階級コードか）
  - 階級コードの一覧とその件数（`depth_class_check.py` の `unmapped_in_data`）
  - `.prj` の内容（座標系名・EPSG コードが分かれば）
  - 外水（河川）・内水のレイヤ／属性が別ファイルか同一ファイル内の区分列かの別
- **判定基準**:
  - `depth_class_check.py` が `unmapped_in_data` を返さない（実データの階級コードがすべて `pipelines/config/depth_class_tables.json` の想定区分でカバーされる）→ 写像表の `verified` を `true` に更新するだけでよい。
  - `unmapped_in_data` がある、または階級区分の数・境界値が想定（6区分: 0.1未満/0.1-0.5/0.5-1.0/1.0-2.0/2.0-5.0/5.0以上）と異なる → `pipelines/config/depth_class_tables.json` の `tokyo_inundation_map.class_codes` を実データに合わせて更新してから ETL を実行する。
  - 座標系が測地成果2011平面直角座標系第9系（想定 EPSG:6677）と異なる場合は、ETL 側で座標変換ステップの追加が必要（`03_スコアリング仕様.md` の空間結合前提の見直し）。
- **結果の反映先**: `pipelines/config/depth_class_tables.json`（`tokyo_inundation_map` の `class_codes`/`verified`/`note`）、`docs/04_データカタログ.md` #2 行の「確からしさ」「形式・座標系」欄、`docs/03_スコアリング仕様.md` H 算出節。

## V-03: 対象区の DEM5A/DEM1A 整備状況・標高タイル最大ズーム

- **検証事項**: 対象区の DEM5A/DEM1A 整備状況、標高タイルの最大ズーム。
- **取得元 URL**:
  - タイル本体: `https://cyberjapandata.gsi.go.jp/xyz/dem5a/{z}/{x}/{y}.txt`（`dem5b`, `dem1a` も同一パターン。タスクカード TASK-006 本文・`docs/04_データカタログ.md` に記載）
  - 仕様: `https://maps.gsi.go.jp/development/demtile.html`

- **取得手順（ログイン・API キー要否）**: 不要（無償・出典明示で商用可、基本測量成果ではなく申請不要）。
- **実行コマンド**:
  ```bash
  # URL 列挙のみ（通信なし）
  python3 tools/verify/tile_probe.py --zoom 15

  # ネットワーク制限のない環境で到達確認（実際に叩いて 200/404 を見る）
  python3 tools/verify/tile_probe.py --zoom 15 --layers dem5a,dem5b,dem1a \
    --fetch --max-per-layer 30 --json-out docs/verification/_work/v03_z15.json

  # 最大ズームの見極め：ズームを上げながら再実行し、どこで 404 が増えるか確認する
  python3 tools/verify/tile_probe.py --zoom 17 --layers dem5a,dem1a \
    --fetch --max-per-layer 30 --json-out docs/verification/_work/v03_z17.json
  ```
- **手作業確認（整備状況ビューア）**: 地理院地図（`https://maps.gsi.go.jp/`）を開き、標高タイルのレイヤ選択から DEM5A/DEM1A の整備範囲を目視確認する方法でも代替できる（具体的な「整備状況ビューア」専用ページの URL は本調査では特定できていないため、地理院地図での目視確認を代替手段として明記する）。
- **記録すべき結果**:
  - `dem5a`/`dem5b`/`dem1a` それぞれの到達率（`reachable_rate`）
  - 到達可能な最大ズームレベル
  - 目黒区・世田谷区の範囲内で欠測タイルがある場合はその位置（bbox の中でどのあたりか）
- **判定基準**:
  - `dem5a` が対象区内でほぼ全域（目安: 到達率 95% 以上）取得できる → 相対標高算出の一次ソースとして採用（`ground_elev_m`/`rel_elev_m` を Tier 0 とする）。
  - `dem1a`（1m メッシュ、都市部限定）が一部でも取得できる場合、その範囲だけ `dem5a` より優先して使う設計にする（より高精度）。
  - `dem5a` にも欠測がある区域は、`dem5b`（5m メッシュ第2区分）や国土数値情報の標高メッシュ等の代替を検討し、それも無ければ `rel_elev_m`/`depression_flag` を Tier 2（信頼度低）として扱う。
- **結果の反映先**: `docs/03_スコアリング仕様.md`（`ground_elev_m`/`rel_elev_m`/`depression_flag` の Tier 設計）、`docs/04_データカタログ.md` #4 行、`pipelines/30_terrain.py` の実装（本タスクでは編集しない。反映は別タスク）。
