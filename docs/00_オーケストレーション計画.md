# 開発オーケストレーション計画

- 作成日：2026-09-09
- 位置づけ：本プロジェクトを「上位モデル（Fable）が計画・指示・監督、下位モデル（Sonnet/Haiku）が実装・調査」で進めるための運用ルール

## 1. 役割分担

| 役割 | 担当モデル | 主な仕事 | やらないこと |
|---|---|---|---|
| PM / アーキテクト / レビュアー | Fable 5.1 | 要件確定、設計判断、タスク分割、受入基準の定義、成果物レビュー、コミット可否判断 | 大量のコード記述、機械的な調査 |
| 調査員 | Sonnet 5 | WebSearch によるオープンデータ・事例・競合調査、出典付きレポート作成 | 要件の決定 |
| 実装者 | Sonnet 5 | タスクカードに基づくコード・テスト・ドキュメント実装 | 受入基準の変更、スコープ拡大 |
| 補助作業者 | Haiku 4.5 | 定型変換、フォーマット、テストデータ生成、単純リファクタ | 設計を伴う変更 |

## 2. 作業サイクル

1. Fable が `docs/tasks/` にタスクカードを書く（目的・入力・出力・受入基準・禁止事項）。
2. 下位モデルに Agent ツールで委任する。独立タスクは並列起動する。
3. 成果物は必ず Fable がレビューする（差分を読む、テストを実行する、受入基準に照らす）。
4. 不合格なら差し戻し理由を具体的に書いて再委任する。合格ならコミットする。
5. 設計判断・前提の変更は Fable のみが行い、`docs/02_要件定義書.md` の「決定事項」に追記する。

## 3. タスクカードの書式

```text
# TASK-xxx タイトル
- 目的：
- 前提・制約：
- 入力（読むべきファイル）：
- 出力（作るファイル）：
- 受入基準（チェックリスト）：
- 禁止事項：
- 完了報告に含めること：
```

## 4. 品質ゲート

- 純 Python 部分：`python -m unittest` が通ること。外部ライブラリ不要で動くこと。
- GIS 前処理部分：この開発環境では PyPI に到達できないため実行検証できない。冒頭に必要ライブラリを明記し、入出力スキーマをテストで固定する。
- ドキュメント：推測と確認済み事実を分ける。出典 URL を付ける。
- コミットメッセージにモデル名を含めない。

## 5. 環境制約（2026-09-09 時点）

- WebFetch・curl は egress 制限で外部ドメインにほぼ到達不可。WebSearch のみ利用可。
- PyPI・npm に到達不可。Python 3.11 標準ライブラリ + PyYAML のみ利用可。
- したがって、オープンデータの実ダウンロード・GIS 演算の実行は、ネットワーク制限のない環境（ローカル PC 等）で行う。本リポジトリでは ETL スクリプトと仕様を整備し、スコアリングエンジンとテストデータで動作を保証する。
